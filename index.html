Unreleased Project

06/2022 - 07/2023
Unreleased third-person shooter

My role was divided into two areas of gameplay: prototyping player states and designing a modular weapon system.

Player states utilised a combination of the Gameplay Ability System (GAS) and a custom state machine implementation. I was responsible for implementing the death/respawn cycle along with the states required for one of the game's primary movement abilities.

The modular weapon system was designed to overhaul the existing static weapon system and allow the design team to experiment with various firearm mechanics to quickly iterate on weapon archetypes. I was given ownership of the system and collaborated with code and design teams to construct a prototype, which was presented to stakeholders in a feature review meeting.

The system used UObject "modules" which encapsulated various mechanics and variations of mechanics, such as firing mechanisms, ammunition types and stat changes. These modules could be instanced in editor to edit properties and then compiled in a weapon Blueprint which had sections to allow modules to be active always, while hipfiring or while aiming.

For example, a configuration with an automatic trigger and standard rounds in hipfire and a semi-auto trigger, explosive rounds and FOV modifier while aiming could be used for an assault rifle with an underbarrel grenade launcher.

Sackboy: A Big Adventure

08/2020 - 11/2020 | 07/2018 - 08/2019

My role was divided into two timeframes, which each had a different development focus.

My later role was during the months leading up to the game's release and involved maintaining and polishing Sackboy's abilities. Some notable features I was responsible for include:

  • Certain areas provided the means for the player to get stuck between a sloped wall and a crate, which was fixed with the entertaining solution of automatically triggering Sackboy's "slap tornado" to destroy the crate.
  • Ledge grabbing while holding an object would inconveniently drop the object and so an automatic throw and catch was added to ensure the behaviours would stylishly avoid eachother without the object falling.
  • While holding a large crate Sackboy could slide the crate over some high steps, resulting in him helplessly dangling from beneath the crate, which was fixed by giving his arms a minimal amount of stretching to raise the object.

My earlier role was during my Placement in the game's pre-alpha/alpha stages of development, where I was responsible for developing an "automated player" for QA and testing purposes. The system used a manager to send actions to one or more virtual controllers, which would be scripted in Level Blueprint and would include periodic result outputs to the logs. Once compiled into a build, an external Runner application could download the latest stable package mcpackageface, run a specified level on a devkit and collate the results from the logs. The results would then be sent to a Server, which had the dual purpose of storing results to be viewed from a web frontend and allowing users to request a specific test to be run.

I additionally collaborated with the core-tech and art teams to adapt a lightweight version of the Runner/Server to be used for automated lighting builds.

Azimov

07/2024 - Present

Named after famous science-fiction writer Isaac Azimov and inspired by the game Bots Are Stupid, the player controls one or more drones using a simple scripting language to complete tasks ranging from simple navigation to complex parallel control.

The project uses a 3D grid-based environment and lockstep timing system, with each step being referred to as a "cycle". This ensures the scripting language to remains simple, as each action occurs over a single cycle, and allows the player to more easily sync actions to the world. To assist with iteration, world's simulation can be started and stopped at any time by the player, allowing them to observe the world before scripting and validate completed scripts.

An example drone script for simple object manipulation is as follows:

repeat 5
    move forward
turn right
repeat 3
    move forward
grab
repeat 6
    move backward
repeat 2
    turn left
drop

The project also features a Minecraft Redstone inspired "circuit" system which drives the puzzle logic, allowing the player to visually identify features such as connections, timers and buttons through physical wires and components in the world.

VR Experiment

04/2022 - 06/2022

An experiment with Unreal's VR API which included basic world interaction and a simple gesture-based "magic" system.

The experiment used a Valve Index to allow for hand tracking, which was enhanced with a system to detect in-world surfaces and feed the data to the hand's IK to stop individual fingers on surfaces. The system could also record the user's grip strength based on the weighted average of the hand's curl values, allowing the user to pick up objects with an "interaction" component simply by having a secure grip on the object. Two-handed lifting was also supported and the object would determine a pivot point based on the grab positions to assist in making object manipulation feel more natural.

The "magic" system was added on top of the base framework to prototype a game mechanic concept I had at the time. The system used a combination of hand signs and an "aspect" system to produce various effects. Aspects were created using the index finger while holding a button with the thumb to link points on a grid in front of the player and draw shapes, which was inspired by pattern-style phone lock screens.

Stealing Stuff

01/2020 - 05/2020

An arcade-style game developed for a final year university group assignment where a team of players is tasked with sneaking around a neighbourhood and stealing every object which isn't nailed down.

Game Republic Student Showcase 2020
This project achieved 3rd place in both the Sumo Digital Award for Game Design and Rockstar Leeds Award for Best Team categories

My role involved acting as the lead programmer, which alongside programming various gameplay mechanics additionally involed delegating tasks to the other programmers. I implemented many of the game's core mechanics, including but not limited to:

  • Dynamic character controls with two distinct modes: world relative and object relative. World relative was the default and moved along cardinal directions, while object relative moved to push/pull/rotate a large object.
  • A multiplayer camera rig which provided a 2.5D perspective and would adjust its distance from a focal point to enure all active players remained on screen.
  • The object interaction system which allowed players to pickup and drop objects. Smaller objects had a low lift force and could be moved alone, while larger objects had a high lift force and required multiple players to move. When moving larger objects, the object determines a pivot point based on the player grab positions which is used to drive the player's object relative movement mode.

Modular Weapons

09/2019 - 05/2020

A modular weapon system developed for a final year university assignment which empowers the user to construct weapons from modules and modify properties at runtime. This project would later be used as inspiration for a more refined system developed for an unreleased project during my time at Sumo Digital.

The system is comprised of the main weapon Blueprint and numerous UObject modules which are inserted at runtime, either through manual selection or by using the save/load system to load a configuration from a generated string. Modules are split into "cores" and "modifiers":

  • Cores encapsulate base weapon attributes, such as the weapon archetype, trigger type, damage, fire rate, reload speed, etc. Cores are named after data structures, such as "scalar" which fires a single projectile (rifle), "struct" which fires many projectiles simultaneously (shotgun) and "vector" which fires a beam.
  • Modifiers add additional behaviours to projectiles, such as ricochet or homing, and were designed to be able to function in parallel with eachother

Once a module has been inserted into the weapon it can be selected in the runtime interface to modify its properties. These properties use small structs representing specific data types (boolean, integer, float, custom, etc.) with delegates to allow the weapon to detect changes and react appropriately.

Blackjack

02/2018

A simple windows console version of the popular card game "Blackjack" developed in my free time to practice skills learned during university.

The project featured a standard turn based approach, where players would perform an action each round until a winner was determined. Players could enter a name before starting and a simple AI player known as "Dealer" was also present, allowing the game to be played with only a single player. An STL vector represented the deck and was used to store cards, which provided out-of-the-box shuffling and card duplication prevention.

A second iteration was later created in 2020 with the same mechanics using threading to produce a game engine style separation between gameplay and input.
